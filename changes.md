## newListFrame — selection, motion, removal (2026-11-08)

Rewrote the draft [`gui:newListFrame`](addons/extensions.lua:197) into a finished list widget: scrollable single-selection rows on `newScrollFrame`, with hover/press/selection transitions, animated add/remove, and optional keyboard nav.

- **Bug fixes in the draft:** `removeRox`/`:Destroy()` (neither existed) → `remove` calling lowercase `destroy` with `table.remove` (no array hole); `row:OnReleased(function() box:select(i) end)` captured a stale index (wrong selection after any removal) — selection is now tracked by row identity and public indices are *live* indices that skip collapsing rows; unselected rows were filled with `th.primaryText`, painting solid bars under same-colored labels (invisible text) — unselected rows are now transparent and only selection/hover/press/stripe paint.
- **Motion:** one shared `OnUpdate` tween loop per list (exponential settle, ~150 ms, interruptible — retargets continue mid-flight; the loop sleeps when idle). Adds fade + 8 px slide with 40 ms stagger (capped); removes fade out, lose text first, then collapse height while neighbours reflow from target heights, retiring the row only when its exit finishes. Selection color lerps for pointer input but **snaps instantly for keyboard** (never animate a key used hundreds of times a day). `animate=false` lands state same-frame.
- **Interaction:** hover tint (lightened `primaryBG`), press darken, double-click (0.35 s window) and right-click hooks, `ensureVisible`-style smooth scroll only when the selected row is actually clipped, empty-state placeholder (`emptyText`), `striped` rows whose parity survives removals, focus tracking (press inside focuses, `OnPressedOuter` defocuses; `setFocused` override).
- **API:** `add/insert/setItems/remove/removeValue/clear`, `select/setSelected` (silent), `getSelected/getItem/getItems/getItemCount/getRow/indexOf/isEmpty/scrollToShow/isSettling/setFocused/isFocused`, `OnSelectionChanged` connection, color overrides (`selectedColor/hoverColor/stripedColor/textColor/emptyTextColor/backgroundColor`); `removeRox` kept as a deprecated alias.
- **Framework gotchas solved along the way:** fill alpha rides `visibility` (the draw path ignores `color[4]`) and text alpha `textVisibility`; collapsing rows are floored at 2 px because `scaleFont` derives font size from element height (`newFont(0)` errors); a full-width invisible spacer keeps `autoMeasure`'s content-width pin stable when the list empties; the pump tracks its own wall-clock dt (`love.timer.getDelta` is per-frame and shared; the updater thread can be starved ≥1 s by the unfocused-window 10 FPS cap — no upper dt clamp, a starved tick converges with k→1).
- **Tests:** new [`examples/list-demo/`](examples/list-demo/main.lua:1) demo + autotest (`love examples/list-demo --list-autotest`) — **54 checks, 0 failures**: layout math + autoMeasure extent, selection events, the invisible-text regression, remove/insert/removeValue with reflow + selection reassignment, off-screen select → smooth scroll, simulated clicks through the real input pipeline (press cleanup, double/right click, click-away defocus), keyboard nav snapping + Delete, placeholder fade, rapid add/remove interruption, worst case (303 rows incl. empty/one-char/long unbreakable labels). flex (headless, all PASS), grid (79/0), svg (96/0) unchanged.
- **Docs:** new [widgets §12](docs/widgets.md:1) (legacy auto-stacker moved to §13 with an override warning), constructor row in [api-quick-reference](docs/api-quick-reference.md:1), module lists in [docs/README](docs/README.md:1) and root README.

## svgloader v3 Phases 3–7 — defs/use/symbol, dasharray, gradients, clip-path, masks (2026-11-08)

Completes the approved v3 Tier-2 scope ([`plans/svgloader-plan.md` §H](plans/svgloader-plan.md:226)); autotest now **96 checks, 0 failures**. All of it stays inside [`core/svgloader.lua`](core/svgloader.lua:1) + `examples/svg-demo/` — the `init.lua` hookup and raster pipeline remain untouched.

- **Two-phase parser** ([`SVG.parse`](core/svgloader.lua:1)): the streaming v1 pass (which discarded `defs`, making `url(#id)` and forward `use` structurally impossible) is replaced by (1) an element tree registering every `id` into `doc.defs`, then (2) a flatten pass that inherits style/transform, expands `use`/`symbol` (depth cap 8, `href`/`xlink:href`, `x`/`y`, own transform + presentation attrs, `symbol` `viewBox` → scale), and compiles shapes through the unchanged `addShape`/`doc.shapes` contract.
- **Group opacity** folded multiplicatively into `fillAlpha`/`strokeAlpha` during flatten (`<g opacity>` now works).
- **stroke-dasharray/dashoffset** ([`dashTessellate`](core/svgloader.lua:1)): static-geometry arc-length walk emitting alternating on/off spans as separate strip meshes (odd-length arrays doubled per spec, `dashoffset` consumed as a leading partial run); **butt/square caps** extend open spans by w/2. `stroke-linejoin` maps to `setLineJoin`/`setLineStyle`; `round` cap/join approximated via `setLineStyle("smooth")` — this build has no `setLineCap` and `setLineJoin` rejects `"round"` (probed).
- **Gradients** (`fill="url(#id)"`): `linearGradient`/`radialGradient`/`stop` parsing (offsets incl. `%`, `stop-color`/`stop-opacity`), 256×1 ramp ImageData → linear-filtered texture, drawn as a UV-mapped mesh over the shape bbox under the normal shape stencil. `gradientUnits` (objectBoundingBox default + userSpaceOnUse, incl. `%` resolution) and `spreadMethod` (`repeat`/`reflect` via texture wrap). Unknown id → fill none + warn (spec behavior). Limits: `gradientTransform` ignored, radial `fx`/`fy` treated as center.
- **clip-path**: **geometric** Sutherland–Hodgman clipping at load time (the planned nested-stencil design is impossible in this build — writes reset per `stencil()` call and are suppressed under an active test). Convex regions only (rect/circle/ellipse/convex polygon, incl. flattening); multiple children intersect; concave children warn once and the clip is skipped; `clipPathUnits` both modes.
- **mask**: pure-Lua 96×96 luminance→alpha rasterization (sRGB weights, documented deviation from the spec's linearRGB) with the shape's fill color baked in, so a masked fill draws as a tinted textured quad — same path as gradient meshes, no shader, no canvas stencils. `maskUnits` (with SVG's −10%/120% region defaults) + `maskContentUnits` both supported; solid-fill mask children only; gradient+mask on one shape → gradient wins.
- **Tests** ([`examples/svg-demo/main.lua`](examples/svg-demo/main.lua:1)): 54 → **96 checks** — signed-area/convexity/S-H area+disjoint/point-in-poly units; dash span positions, offset trim, odd-array doubling, square-cap extents; stop parsing + 256px ramp endpoints + unknown-`url` no-shape; tree fixture (6 shapes, opacity fold, symbol 4× scale, `use` translation, forward-ref registry, unknown-id skip); render boxes + pixel probes for fill-rule, geometry, tree, **gradients** (linear left/right/mid + radial center/edge/clamp), **clip-path** (disc center/inside/corner-outside/below), **mask** (stripe 1/gap/stripe 2/pre-gap). Window reflowed for the 7 boxes.
- **Docs**: [`docs/core-modules.md` §4](docs/core-modules.md:198) and [`docs/elements.md` §4.4](docs/elements.md:295) rewritten — they previously claimed gradients/masks/arcs were unsupported, which is now false; the loader header's supported/unsupported lists match.

## svgloader v3 Phases 0–2 — probes, nonzero fill-rule, full Tier-1 geometry (2026-11-08)

First implementation slices of the approved v3 expansion ([`plans/svgloader-plan.md` §H](plans/svgloader-plan.md:226)): environment probes, the fill-rule correctness fix, and the complete Tier-1 geometry set. Tier 2 (defs/use, gradients, clip/mask, dasharray) remains planned.

- **Probe (throwaway [`../tmp-svgprobe`](../tmp-svgprobe/main.lua:1), results in plan §H.1):** this stripped LÖVE 11.5 build has **no** `love.math.newPath`/`setFillMode`/`setLineCap`/`newScreenshot` (Path & line caps are LÖVE 12.0 APIs — the loader header's "added in 11.4" was wrong), **no canvas stencil attachments or `samples`**, stencil **writes are suppressed while a stencil test is active**, and the stencil buffer **resets at the start of every `love.graphics.stencil()` call** (two draws inside ONE call accumulate; separate calls do not). These facts killed the planned per-contour inc/dec winding passes and the nested-stencil clip-path design; the plan now specifies geometric contour clipping for clip-paths and canvas+shader masks.
- **Fix — fill-rule nonzero** ([`core/svgloader.lua`](core/svgloader.lua:1)): was silently rendered as even-odd (most real SVGs default to nonzero). Now one baseline `replace 0` pass, then exactly ONE contour-writing stencil call per shape: evenodd → `invert`; nonzero all-same-orientation → `increment` (exact winding≠0 for the uniform case, chosen at build time via shoelace signed area); nonzero mixed orientations → even-odd approximation + warn once. Stencil test set only after all writes.
- **Tier-1 geometry** ([`core/svgloader.lua`](core/svgloader.lua:1)): **`A a` arcs** — endpoint→center per SVG spec F.6.5 (incl. `rx 0` and out-of-range radius corrections) split into ≤90° cubic segments through the existing flattener; **flag-aware path scanner** so `A … 0 01 8 8` splits the `01` flags correctly (the plain scanner glued them into one number); **`rect rx/ry`** — rounded-rect contours via the KAPPA quarter-cubic machinery, radii clamped to half sides, `rx`⇄`ry` defaulting; **transform matrices** — the axis-aligned `{sx,sy,tx,ty}` model replaced by 2×3 affine composition (`translate`/`scale`/`rotate(θ cx cy)`/`skewX`/`skewY`/`matrix`, SVG left-to-right list order) in `parseTransform`/`inheritFrom`/`xformContour`; **units** — `numAttr` now resolves `pt/pc/mm/cm/in/em/%` (96 dpi, root font 16, viewport basis per attribute); **preserveAspectRatio** — `xMin|xMid|xMax` + `YMin|YMid|YMax` + `meet|slice` + `none` honored in `:draw` (default xMidYMid meet unchanged).
- **Tests** ([`examples/svg-demo/main.lua`](examples/svg-demo/main.lua:1)): autotest grew 24 → **54 checks, 0 failures** — signed-area units; arc endpoint/bulge/no-NaN units + flag-split scanner; rounded-rect bounds; `rotate(90)`/composition-order matrix units; unit conversions; two fill-rule pixel fixtures (same overlapping squares, opposite overlap treatment) with 6 discrimination probes; one geometry fixture (`rx` + `rotate(45)` + semicircular arc) with 7 render probes. Bookmark-vs-PNG pixel diff unchanged (mean 1.61/255/ch, 0 disagreements) throughout the matrix refactor.
- **Not changed:** the `init.lua` hookup, raster pipeline, docs prose (module header updated in place; docs refresh rides Phase 7).

## SVG vector loader — live-drawn SVGs in image elements (2026-11-07)

New `setImage("*.svg")` path that renders SVGs as **vectors**, drawn live every frame at the element's current box size — so they stay crisp at any scale (fixed, flex, `dualDim`, window resize), unlike the raster path. Mirrors `core/gifloader.lua`'s module shape (`load()` → duck-typed object with `getWidth`/`getHeight`); no thread/animator since SVGs are static.

- **Core:** [`core/svgloader.lua`](core/svgloader.lua:1) — XML-lite parser (attrs, `<g>` inheritance + `translate`/`scale`, `<defs>`/`text`/gradients skipped), token scanner (implicit sign separators, exponents), path-command executor (`M m L l H h V v Z z` exact; `C c S s Q q T t` flattened to polylines; `A a` warned-and-skipped), shape builders (`rect`/`circle`/`ellipse`/`line`/`polyline`/`polygon`), paint parser (`#RGB`/`#RRGGBB`/`rgb()`/named/`none`, opacity, `fill-rule`). Geometry built once per file and cached; drawn via `love.math.triangulate` → meshes → one `love.graphics.stencil(...,"invert")` parity pass + bbox fill (even-odd holes punch correctly), strokes via line-strip meshes. This build has no `love.math.newPath`/Path, hence the stencil-parity approach; anti-aliasing comes from window MSAA, not the loader.
- **API:** [`svg.load(path)`](core/svgloader.lua:1) → cached object with `:draw(x,y,w,h,{rotation,scaleX,scaleY,alpha})`, `getWidth`/`getHeight`; module-level `getInfo`, `clearCache`. [`init.lua` `setImage`](init.lua:2025) branches on `.svg`: parses, leaves `c.image = nil` (image draw pass no-ops via its `if child.image` guard), sets `imageWidth/Height` from intrinsic size, and installs a `post` overlay hook re-reading `getAbsolutes()` each frame; `__isSvg` marks the element and a non-SVG `setImage` clears the overlay (user-set `post` untouched). Rotation/flip follow the image pipeline's sign conventions.
- **Not changed (deliberately):** the raster `image_cache` and draw-type pipeline — SVGs bypass both, so PNG/GIF behavior is byte-identical and `imageColor` tinting simply doesn't apply to vectors (documented limitation).
- **Tests:** [`examples/svg-demo/`](examples/svg-demo/main.lua:1) autotest (`love examples/svg-demo --svg-autotest`) — 24 checks, 0 failures: parse/cache/color/contour units, a window-capture pixel-diff of the 200px SVG vs the reference `bookmark-svg.png` (mean 1.61/255/ch, **0 white-vs-fill shape disagreements**, four shape probes at d=0.000), and 400px crispness probes. Interactive window shows PNG vs SVG at 200/400px plus a scripted 130↔215px resize ping-pong (both crisp) — screenshot-verified.
- **Docs:** [`docs/core-modules.md` §4](docs/core-modules.md:145) (user guide, pipeline diagram, supported-subset & limitations); new [`docs/elements.md` §4.4](docs/elements.md:277); [`docs/api-quick-reference.md`](docs/api-quick-reference.md:188) row; [`docs/architecture.md`](docs/architecture.md:497) cache note; [`docs/README.md`](docs/README.md:43) file tree. Plan at [`plans/svgloader-plan.md`](plans/svgloader-plan.md:1).

## VisualEvents identity filter — window theming leaked across the whole app (2026-11-04)

`obj:OnExit` / `OnPressedOuter` / `OnReleasedOuter` / `OnReleasedOther` / `OnDrag*` / `OnSizeChanged` / `OnPositionChanged` (the `VisualEvents` set) were installed behind a façade that filtered only `testVisual(obj)` — never `obj == self` — unlike the `HierarchyEvents` and `BasicEvents` façades ([`init.lua:1060-1078`](init.lua:1060)). Because the underlying `_OnXxx` connections are global and fired with the element that owns the event, a handler registered on element A ran for **every** element's event with that foreign element as `self`.

Consequence in the app: creating any `newWindow`/`newMessageBox` permanently themed the whole GUI, since the window styles its buttons with `el:OnExit(function(self) self.color = th.button end)` ([`addons/system.lua:492-493`](addons/system.lua:492)) and its close button with an `OnExit` that sets `#e50000` (`:359-360`). After opening one message box, every element that left hover was repainted the window's button color — and `root:close()` only reparents to `gui.virtual` (`:471-474`), so the handlers survived the box.

- **Fix:** the VisualEvents façade now applies `obj == self and testVisual(obj)`, mirroring the HierarchyEvents façade. Strict narrowing: every in-repo consumer either already guarded `obj == self` (`addons/system.lua` drag/thumb handlers, `core/flexbox.lua:1136`, `core/grid.lua:516`) or needs per-object semantics (textbox `OnPressedOuter` unfocus at `init.lua:1548`, extensions' color-picker/radio commit, scroll thumbs). No escape hatch needed.
- **Not changed (deliberately left as belt-and-braces):** the consumer-side `if obj == X then` guards, so those handlers stay correct independent of façade rules.
- **Also fixed in the same pass:** `X:OnExit(function(self) self.color = … end)` and `el:OnExit(function(self) … end)` in `newWindow` were already correct once filtered; the file-picker rows (`:799`, `:908`) and textbox cursor reset (`init.lua:1718`) were silently mis-firing on foreign elements and are now scoped.
- **Tests:** `--window-hovertest` probe in the jeopardy app drives title → EDITOR → Save → message box and fires `gui._OnExit` at all editor nodes, asserting zero foreign recolors with no window / with the window / after closing — 0/0/0 (was 24/24/24). `--editor-clicktest`, `--editor-autotest`, `--flex-autotest` 78/78, `--grid-autotest` 79/79 all still pass.
- **Docs:** filter table in [`docs/architecture.md`](docs/architecture.md:272) and the dirty-marking note in [`docs/flexbox.md`](docs/flexbox.md:183) updated; the "VisualEvents do NOT filter by obj" comments in `addons/system.lua`, `core/flexbox.lua:1126`, `core/grid.lua:510` corrected.

- **Core:** [`core/grid.lua`](core/grid.lua:1) implements the grid root pass — track-list/areas/placement parsers (parsed once at `setGrid` time), placement engine (explicit/negative lines, spans, areas, auto-flow row|column, dense, implicit tracks), track sizing (`px`/`auto`/`min-content`/`minmax`/`fr` + gaps), content + item alignment, Pass-B text wrap + auto-row re-solve, and `grid.intrinsic` for the cross-mode fit contribution.

## Opt-in flexbox layout system (Phases 1–6)

New opt-in flexbox layout for the GUI, fully backwards compatible — elements that never call it are untouched.

- **Core:** [`core/flexbox.lua`](core/flexbox.lua:1) implements the layout pass (row/column, percent widths, grow/shrink, min/max clamps, wrap, aspect ratio, alignment, floating children, dirty-gated re-layout, re-entrancy-safe `runPass`); [`core/measure.lua`](core/measure.lua:1) is a cached text-measure service backing fit-content sizing.
- **API:** [`setFlex`](core/flexbox.lua:1159) configures a container's flex properties; [`setSizing`](core/flexbox.lua:1160) opts an element into (or out of) size management. Managed elements get dualDim write-back (offset + size), so all existing positioning/collision/scroll logic keeps working; manual geometry calls (`move`/`size`/`setDualDim`) escape the element to floating.
- **Hooks:** [`init.lua`](init.lua:7) loads the module via `pcall` and nil-guards every hook site (manual-geometry escape hatch, parent/child/destroy dirtying, draw-loop pre-pass, virtual refresh, late injection) — a missing module leaves the GUI byte-identical to before.
- **YAML:** [`yaml/builder.lua`](yaml/builder.lua:1) accepts `flex:` and `sizing:` keys on declarative elements; scroll containers auto-fit content height (`fit-content`, `maxScrollY` derived, no manual `setContentSize`).
