## SVG vector loader — live-drawn SVGs in image elements (2026-11-07)

New `setImage("*.svg")` path that renders SVGs as **vectors**, drawn live every frame at the element's current box size — so they stay crisp at any scale (fixed, flex, `dualDim`, window resize), unlike the raster path. Mirrors `core/gifloader.lua`'s module shape (`load()` → duck-typed object with `getWidth`/`getHeight`); no thread/animator since SVGs are static.

- **Core:** [`core/svgloader.lua`](core/svgloader.lua:1) — XML-lite parser (attrs, `<g>` inheritance + `translate`/`scale`, `<defs>`/`text`/gradients skipped), token scanner (implicit sign separators, exponents), path-command executor (`M m L l H h V v Z z` exact; `C c S s Q q T t` flattened to polylines; `A a` warned-and-skipped), shape builders (`rect`/`circle`/`ellipse`/`line`/`polyline`/`polygon`), paint parser (`#RGB`/`#RRGGBB`/`rgb()`/named/`none`, opacity, `fill-rule`). Geometry built once per file and cached; drawn via `love.math.triangulate` → meshes → one `love.graphics.stencil(...,"invert")` parity pass + bbox fill (even-odd holes punch correctly), strokes via line-strip meshes. This build has no `love.math.newPath`/Path, hence the stencil-parity approach; anti-aliasing comes from window MSAA, not the loader.
- **API:** [`svg.load(path)`](core/svgloader.lua:1) → cached object with `:draw(x,y,w,h,{rotation,scaleX,scaleY,alpha})`, `getWidth`/`getHeight`; module-level `getInfo`, `clearCache`. [`init.lua` `setImage`](init.lua:2025) branches on `.svg`: parses, leaves `c.image = nil` (image draw pass no-ops via its `if child.image` guard), sets `imageWidth/Height` from intrinsic size, and installs a `post` overlay hook re-reading `getAbsolutes()` each frame; `__isSvg` marks the element and a non-SVG `setImage` clears the overlay (user-set `post` untouched). Rotation/flip follow the image pipeline's sign conventions.
- **Not changed (deliberately):** the raster `image_cache` and draw-type pipeline — SVGs bypass both, so PNG/GIF behavior is byte-identical and `imageColor` tinting simply doesn't apply to vectors (documented limitation).
- **Tests:** [`examples/svg-demo/`](examples/svg-demo/main.lua:1) autotest (`love examples/svg-demo --svg-autotest`) — 24 checks, 0 failures: parse/cache/color/contour units, a window-capture pixel-diff of the 200px SVG vs the reference `bookmark-svg.png` (mean 1.61/255/ch, **0 white-vs-fill shape disagreements**, four shape probes at d=0.000), and 400px crispness probes. Interactive window shows PNG vs SVG at 200/400px plus a scripted 130↔215px resize ping-pong (both crisp) — screenshot-verified.
- **Docs:** [`docs/core-modules.md` §4](docs/core-modules.md:145) (user guide, pipeline diagram, supported-subset & limitations); new [`docs/elements.md` §4.4](docs/elements.md:277); [`docs/api-quick-reference.md`](docs/api-quick-reference.md:188) row; [`docs/architecture.md`](docs/architecture.md:497) cache note; [`docs/README.md`](docs/README.md:43) file tree. Plan at [`plans/svgloader-plan.md`](plans/svgloader-plan.md:1).

## VisualEvents identity filter — window theming leaked across the whole app (2026-11-04)

`obj:OnExit` / `OnPressedOuter` / `OnReleasedOuter` / `OnReleasedOther` / `OnDrag*` / `OnSizeChanged` / `OnPositionChanged` (the `VisualEvents` set) were installed behind a façade that filtered only `testVisual(obj)` — never `obj == self` — unlike the `HierarchyEvents` and `BasicEvents` façades ([`init.lua:1060-1078`](init.lua:1060)). Because the underlying `_OnXxx` connections are global and fired with the element that owns the event, a handler registered on element A ran for **every** element's event with that foreign element as `self`.

Consequence in the app: creating any `newWindow`/`newMessageBox` permanently themed the whole GUI, since the window styles its buttons with `el:OnExit(function(self) self.color = th.button end)` ([`addons/system.lua:492-493`](addons/system.lua:492)) and its close button with an `OnExit` that sets `#e50000` (`:359-360`). After opening one message box, every element that left hover was repainted the window's button color — and `root:close()` only reparents to `gui.virtual` (`:471-474`), so the handlers survived the box.

- **Fix:** the VisualEvents façade now applies `obj == self and testVisual(obj)`, mirroring the HierarchyEvents façade. Strict narrowing: every in-repo consumer either already guarded `obj == self` (`addons/system.lua` drag/thumb handlers, `core/flexbox.lua:1136`, `core/grid.lua:516`) or needs per-object semantics (textbox `OnPressedOuter` unfocus at `init.lua:1548`, extensions' color-picker/radio commit, scroll thumbs). No escape hatch needed.
- **Not changed (deliberately left as belt-and-braces):** the consumer-side `if obj == X then` guards, so those handlers stay correct independent of façade rules.
- **Also fixed in the same pass:** `X:OnExit(function(self) self.color = … end)` and `el:OnExit(function(self) … end)` in `newWindow` were already correct once filtered; the file-picker rows (`:799`, `:908`) and textbox cursor reset (`init.lua:1718`) were silently mis-firing on foreign elements and are now scoped.
- **Tests:** `--window-hovertest` probe in the jeopardy app drives title → EDITOR → Save → message box and fires `gui._OnExit` at all editor nodes, asserting zero foreign recolors with no window / with the window / after closing — 0/0/0 (was 24/24/24). `--editor-clicktest`, `--editor-autotest`, `--flex-autotest` 78/78, `--grid-autotest` 79/79 all still pass.
- **Docs:** filter table in [`docs/architecture.md`](docs/architecture.md:272) and the dirty-marking note in [`docs/flexbox.md`](docs/flexbox.md:183) updated; the "VisualEvents do NOT filter by obj" comments in `addons/system.lua`, `core/flexbox.lua:1126`, `core/grid.lua:510` corrected.

## Opt-in CSS Grid layout (2026-10-25, Phases P1–P5)

New opt-in CSS-Grid-style layout riding the flexbox scheduler, fully backwards compatible — elements that never call it are untouched, and flex-only trees observe byte-identical behavior.

- **Core:** [`core/grid.lua`](core/grid.lua:1) implements the grid root pass — track-list/areas/placement parsers (parsed once at `setGrid` time), placement engine (explicit/negative lines, spans, areas, auto-flow row|column, dense, implicit tracks), track sizing (`px`/`auto`/`min-content`/`minmax`/`fr` + gaps), content + item alignment, Pass-B text wrap + auto-row re-solve, and `grid.intrinsic` for the cross-mode fit contribution.
- **Generalized scheduler:** [`core/flexbox.lua`](core/flexbox.lua:1) — `isFlexRoot`/`markDirty`/lifecycle hooks/root dispatch generalized to `(e.__flex or e.__grid)`, `writeBack`/`fireGeometryEvents` extracted as shared helpers (byte-identical behavior), `seedAxis`/`propagateUp` consume `grid.intrinsic`, `sizeManaged`/`debugVerifySubtree` accept grid roots; `flexbox.init` installs `gui.setGrid`/`gui.setGridPlacement` via a lazy nil-guarded require, so deleting `core/grid.lua` leaves grid inert with flex fully working. Cross-mode nesting (grid-in-flex, flex-in-grid, grid-in-grid) falls out of the depth-ordered root model.
- **API:** [`setGrid`](core/grid.lua:413) configures a container (columns/rows grammar, areas, gap, autoFlow, dense, `*-items`/`*-content` alignment, `place-*` shorthands); [`setGridPlacement`](core/grid.lua:531) places an item (`"1 / 3"`, `"span 2"`, negative lines, area names) + `justifySelf`/`alignSelf`/`placeSelf`; `setGrid(false)`/`setGridPlacement(false)` remove. Items reuse `setSizing` — default stretch fills the grid area (CSS default; `fit` opts into natural size).
- **YAML:** [`yaml/builder.lua`](yaml/builder.lua:198) accepts `grid:` and `grid-placement:` keys on declarative elements (CSS grammar strings pass through coercion untouched).
- **Demo/tests:** [`examples/grid-demo/`](examples/grid-demo/main.lua:1) runs a headless autotest (`love.exe examples/grid-demo --grid-autotest`) over the plan §6 scenario matrix — 79 checks, 0 failures; the unedited flex-demo remains the existing-behavior regression proof (78 checks, 0 failures).
- **Docs:** [`docs/grid.md`](docs/grid.md:1) (user guide incl. Limitations vs CSS), cross-refs in [`docs/layout-system.md`](docs/layout-system.md:1), [`docs/flexbox.md`](docs/flexbox.md:1), [`docs/api-quick-reference.md`](docs/api-quick-reference.md:1), [`docs/yaml-declarative-ui.md`](docs/yaml-declarative-ui.md:1), [`docs/yaml-based-elements.yaml`](docs/yaml-based-elements.yaml:1); plan at [`plans/grid-integration-plan.md`](plans/grid-integration-plan.md:1).

## Opt-in flexbox layout system (Phases 1–6)

New opt-in flexbox layout for the GUI, fully backwards compatible — elements that never call it are untouched.

- **Core:** [`core/flexbox.lua`](core/flexbox.lua:1) implements the layout pass (row/column, percent widths, grow/shrink, min/max clamps, wrap, aspect ratio, alignment, floating children, dirty-gated re-layout, re-entrancy-safe `runPass`); [`core/measure.lua`](core/measure.lua:1) is a cached text-measure service backing fit-content sizing.
- **API:** [`setFlex`](core/flexbox.lua:1159) configures a container's flex properties; [`setSizing`](core/flexbox.lua:1160) opts an element into (or out of) size management. Managed elements get dualDim write-back (offset + size), so all existing positioning/collision/scroll logic keeps working; manual geometry calls (`move`/`size`/`setDualDim`) escape the element to floating.
- **Hooks:** [`init.lua`](init.lua:7) loads the module via `pcall` and nil-guards every hook site (manual-geometry escape hatch, parent/child/destroy dirtying, draw-loop pre-pass, virtual refresh, late injection) — a missing module leaves the GUI byte-identical to before.
- **YAML:** [`yaml/builder.lua`](yaml/builder.lua:1) accepts `flex:` and `sizing:` keys on declarative elements; scroll containers auto-fit content height (`fit-content`, `maxScrollY` derived, no manual `setContentSize`).
- **Demo/tests:** [`examples/flex-demo/`](examples/flex-demo/main.lua:1) runs a headless autotest (`love.exe examples/flex-demo --flex-autotest`) covering all phases — 81 checks, 0 failures.
- **Docs:** [`docs/flexbox.md`](docs/flexbox.md:1) (user guide) and [`docs/flexbox-integration-plan.md`](docs/flexbox-integration-plan.md:1) (design/plan).
